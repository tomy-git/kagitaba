# kagitaba

[English](README.md) | [日本語](README.ja.md)

`kagitaba` は、macOS向けの**実験的な**APIキー管理CLIです。ローカル環境での利用を前提としています。

APIキーをローカルのmacOS **ログインキーチェーン（Login Keychain）** に保存し、明示的に起動したコマンドに、選択したキーだけを環境変数として渡します。

> ⚠️ セキュリティ上の注意
>
> - このプロジェクトは実験段階であり、独立した第三者によるセキュリティ監査は受けていません。
> - `kagitaba run` で起動したコマンドと、その子プロセスは、渡されたキーを読み取れます。
> - `kagitaba` は、同じユーザー権限で動作する悪意あるプログラムから秘密情報を隔離しません。
> - 子プログラム自身のログ、出力、クラッシュレポートなどから秘密情報が漏れる可能性があります。

## 対応する機能

- `kagitaba set <ENV_NAME>`
  - 秘密情報は、入力内容を表示しないプロンプトで受け付けます。
  - 秘密情報をコマンドライン引数として渡すことはできません。
  - 既存の登録内容を置き換える前に確認します。
  - 入力中に別の処理が同じ名前を登録した場合も、置換の確認が必要です。
- `kagitaba status [ENV_NAME]`
  - 登録状況またはキー名だけを表示します。
  - 秘密情報の値は表示しません。
- `kagitaba run --key <ENV_NAME> [--key <ENV_NAME>...] -- <PROGRAM> [ARGS...]`
  - 選択したキーだけを読み込みます。
  - 子プロセスを直接実行します。シェルのコマンド文字列として評価しません。
  - 子プロセスの終了コードを引き継ぎます。
- `kagitaba delete <ENV_NAME>`
  - 削除前に確認します。
  - kagitabaが管理する項目だけを削除します。

## インストール

[mise](https://mise.jdx.dev/) がインストールされている場合は、次のコマンドを実行します。

```bash
mise trust mise.toml
mise install
mise exec -- cargo build --locked --release
```

実行ファイルは `target/release/kagitaba` に生成されます。

`mise.toml` はRustのバージョンを固定し、Cargo、rustfmt、Clippyをインストールします。RustupとCargoのツールチェーンや依存関係のキャッシュは、このチェックアウト内のGit管理対象外の `.local/` ディレクトリに保存されます。シェルの起動設定や、グローバルなRustの既定設定は変更しません。ただし、mise自身のインストール管理情報、信頼設定、キャッシュはチェックアウトの外にも保存されます。

開発コマンドは `mise exec --` 経由で実行し、プロジェクト専用のパスを適用してください。互換性のあるRust環境がすでにある場合は、その環境でも直接ビルドできます。

miseの共有インストール管理情報は、このチェックアウト内のRust環境を参照します。チェックアウトを移動した場合や、同じRustバージョンを使う別のチェックアウトで作業する場合は、その場所で `mise install` を再実行してください。CargoとRustupのファイルは、各チェックアウトに個別に保持されます。

## 使い方

キーを登録します。

```bash
kagitaba set OPENAI_API_KEY
```

指定したキーの登録状況を確認します。

```bash
kagitaba status OPENAI_API_KEY
```

登録済みのキー名を一覧表示します。

```bash
kagitaba status
```

選択したキーを渡してコマンドを実行します。

```bash
kagitaba run --key OPENAI_API_KEY --key ANTHROPIC_API_KEY -- curl https://example.com
```

キーを削除します。

```bash
kagitaba delete OPENAI_API_KEY
```

## 構成

各層を独立してテストできるよう、コードを分割しています。

- `src/cli.rs`: CLIの引数解析とコマンド構造
- `src/store.rs`: 認証情報ストアのインターフェースとプラットフォーム別の実装
  - macOSでは、`security-framework` バインディングを使用し、専用のサービス名前空間に保存します。
  - macOS以外では、モックによるテストを実行できるよう、実際の保存・取得機能を持たない仮のバックエンドを使用します。
- `src/process.rs`: 子プロセスの実行（プログラム、引数、子プロセスに限定した環境変数の追加）
- `src/app.rs`: コマンド処理、プロンプト、入力検証、ユーザーに見える動作の制御

## キーチェーンとプラットフォームの動作

- 保存先はローカルのログインキーチェーンで、`kagitaba` 専用のサービス名前空間を使用します。
- キーチェーンのロック方針、自動ロック、スリープ時のロック設定は変更しません。
- キーの未登録、アクセス拒否、キーチェーンのロック、プロセスの起動失敗など、想定される失敗は、秘密情報の値を公開せずにエラーとして返します。
- 無効なコマンドライン引数は、その値を表示せずに拒否します。ヘルプとバージョンの表示は利用できます。
- 新規登録では、既存の項目を置き換えません。確認済みの置換では、既存の項目だけを更新します。対象が途中で削除された場合は、再作成せずに処理を失敗させます。
- キー名はキーチェーン項目の属性から取得します。秘密情報の値を読み取ったり、別の索引を管理したりしません。旧形式の索引項目は無視します。
- 子コマンドは通常どおり親プロセスの環境変数を継承し、選択したキーを追加または上書きします。既存の環境変数を除外する処理は行いません。
- アプリケーションが所有する秘密情報のバッファは、破棄時にゼロで上書きします。ただし、RustのプロセスAPIやOSが別のコピーを保持する可能性があるため、メモリからの完全な消去は保証しません。

### シグナルの扱い

`kagitaba run` は子プロセスの終了コードを返します。Unixのシグナルで終了した場合は、シェルと同じ形式で `128 + signal` を返します。

## コード署名とアップグレード

キーチェーンのアクセス許可は、実行ファイルの識別情報、署名、パスに関連付けられる場合があります。そのため、実行ファイルの置換やアップグレード後に、アクセス許可を再度求められる可能性があります。

管理された環境で安定して利用するには、一貫した実行ファイルの署名と配布方法を使用してください。

## 開発

```bash
mise exec -- cargo fmt --all -- --check
mise exec -- cargo clippy --locked --all-targets -- -D warnings
mise exec -- cargo test --locked --all-targets
```

通常のテストはダミーの認証情報とモックを使用し、ログインキーチェーンにはアクセスしません。操作を記録するテスト用の実装で確認操作や失敗経路を検証するほか、キーチェーンの検索条件の構築、キー名の抽出、実行ファイルの引数エラー出力をテストします。
